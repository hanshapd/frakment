Pulse is a compact status timeline for services. Each row is a service, each bar is a day. Hover a bar to swell its neighbors, click to pin the day and reveal its incident log.

## Usage

```tsx title="pulse.tsx"
import Pulse from "@/components/ui/pulse";

<Pulse />;
```

By default, Pulse shows 90 days across four sample services. Pass `services` to provide your own data.

## Anatomy

A Pulse instance has four visible parts.

<ComponentPreview name="pulse" title="pulse.tsx">
  <div className="flex w-full justify-center py-6">
    <Pulse title="API" days={14} services={[{ name: "API", incidents: {} }]} />
  </div>
</ComponentPreview>

- **Header** — title on the left, status badge on the right
- **Summary** — one-line description of the focused day, updates on hover
- **Bars** — one per day, oldest to newest, left to right
- **Pin panel** — opens below the bars when a day is clicked

## Data

Pass a `services` array. Each service takes a `name`, an optional `incidents` map, and an optional `missing` count.

```tsx title="pulse.tsx"
<Pulse
  services={[
    {
      name: "API",
      incidents: {
        12: {
          title: "Elevated latency",
          status: "degraded",
          minutes: 18,
          updates: [
            { time: "14:02", label: "Investigating" },
            { time: "14:20", label: "Resolved" },
          ],
        },
      },
    },
    {
      name: "Database",
      missing: 6,
    },
  ]}
/>
```

- **`incidents`** — keyed by day index. `0` is the oldest day shown, `days - 1` is today.
- **`missing`** — number of days before the service existed. These render as `none` (muted).

## Interaction

Pulse responds to hover, click, and keyboard.

| Input                         | Action                                                               |
| :---------------------------- | :------------------------------------------------------------------- |
| **Hover**                     | The bar under the cursor swells; neighbors ease outward like a dock. |
| **Click**                     | Pins the focused day. Its incident log opens below the bars.         |
| **Click again** or **Escape** | Unpins the day and collapses the log.                                |
| **Arrow keys**                | Move focus between days.                                             |
| **Home / End**                | Jump to the first or last day.                                       |
| **Enter / Space**             | Pin or unpin the focused day.                                        |

## Status colors

Pulse uses color to convey status — a deliberate exception to frakment's monochrome system, because status is a safety signal that must be readable at a glance.

| Status     | Color   | Meaning                              |
| :--------- | :------ | :----------------------------------- |
| `up`       | Emerald | Service operated normally            |
| `degraded` | Amber   | Partial impact                       |
| `down`     | Rose    | Full outage                          |
| `none`     | Muted   | No data (before the service existed) |

## Accessibility

- The timeline renders with `role="slider"` and `aria-valuenow` set to the focused day, so screen readers announce which day is active as you navigate.
- Full keyboard support: arrow keys, `Home`, `End`, `Enter`, `Space`, and `Escape`.
- When `prefers-reduced-motion: reduce` is active, the swell animation is skipped and bar widths snap to their target.
- The pin panel renders with `inert` when closed, so its content is excluded from the tab order and screen readers.
- Color is not the only cue: status is announced through `aria-valuetext` and rendered as text in the pin panel (`Operational`, `Degraded`, `Outage`).
