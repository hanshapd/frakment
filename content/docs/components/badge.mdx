## Anatomy

A badge is a single-part component. It has a bordered surface and a text label. Icons placed inside are automatically sized.

<ComponentPreview name="badge" title="badge.tsx">
  <div className="flex flex-wrap items-center justify-center gap-3">
    <Badge>Text only</Badge>
    <Badge>
      <CheckIcon />
      With icon
    </Badge>
    <Badge variant="outline">
      <PackageIcon />
      v1.2.0
    </Badge>
  </div>
</ComponentPreview>

- **Surface** — background and border, following the variant
- **Text** — 12px, medium weight, nowrap
- **Icon** — 12px, auto-sized by `[&>svg]:size-3`

## Accessibility

- Badges are not interactive unless `asChild` wraps an interactive element such as `<a>` or `<button>`. Do not attach `onClick` handlers to a plain `<Badge>` — use `<Button>` instead.
- When a badge conveys essential information, ensure that information is also present in the surrounding text so screen reader users are not forced to encounter it as a standalone fragment.
- For icon-only badges, provide an `aria-label` so screen readers can announce the intent. Without it, the badge is read as "graphic" or skipped entirely.
- Color alone must not convey state. The `destructive` variant pairs color with text or an icon. When adding custom colors, always include a text label or an icon with an accessible name.
- For badges that indicate a loading state, pair the spinner with a text label such as "Generating" so screen readers can announce what is happening.
- Do not use the `destructive` variant for emphasis. It communicates a failure or prohibition — using it for non-error cases dilutes its meaning.

## Best Practices

- **Use badges for metadata, not actions.** If a badge needs to be clickable, wrap it with `asChild` and an `<a>`, or use a `<Button>` instead.
- **Keep labels short.** Badges are compact by design. Anything longer than 3 words should be a tag, not a badge.
- **Prefer monochrome by default.** Reserve custom colors for status indicators that must be readable at a glance.
- **Pair color with icon or text.** Never rely on color alone to convey state — this is a WCAG requirement and also helps users with color vision deficiencies.
- **Compose with other components.** Badges work best inside `Button`, `Table`, `Card`, or alongside headings. They are not standalone UI elements.
