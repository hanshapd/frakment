Frakment ships an MCP server that exposes the registry as tools. Agents call the tools instead of scraping HTML or writing custom HTTP glue.

## Tools

### list_components

Returns every component with `name` and `description`.

**Input**: none

**Output**: text list of components.

### view_component

Returns the full source of one component.

<PropsTable
  rows={[
    {
      name: "name",
      type: "string",
      description: "Component slug from /r/index.json.",
      required: true,
    },
  ]}
/>

**Output**: markdown with file contents, npm dependencies, and registry dependencies.

### search_components

Case-insensitive substring search across `name` and `description`.

<PropsTable
  rows={[
    {
      name: "query",
      type: "string",
      description: "Free-text search term.",
      required: true,
    },
  ]}
/>

**Output**: matching components with descriptions.

### get_install_command

Returns the exact CLI command.

<PropsTable
  rows={[
    {
      name: "name",
      type: "string",
      description: "Component slug.",
      required: true,
    },
  ]}
/>

**Output**: `npx frakment@latest add <name>`

## Client configuration

<Callout type="info" title="stdio transport">
  Frakment MCP speaks stdio. Launch it from any MCP client that spawns subprocesses.
</Callout>

### Claude Desktop

Config lives at `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS, or `%APPDATA%\Claude\claude_desktop_config.json` on Windows.

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "frakment": {
      "command": "npx",
      "args": ["-y", "frakment-mcp"]
    }
  }
}
```

### Cursor

Config lives at `~/.cursor/mcp.json`:

```json title="mcp.json"
{
  "mcpServers": {
    "frakment": {
      "command": "npx",
      "args": ["-y", "frakment-mcp"]
    }
  }
}
```

### Generic stdio

Any client that spawns stdio processes:

```bash
frakment-mcp
```

## Troubleshooting

<Accordion type="single" collapsible>

<AccordionItem value="404">
<AccordionTrigger>Tool returns HTTP 404</AccordionTrigger>
<AccordionContent>
The component name does not exist in the registry. Call `list_components` first to get a valid slug.
</AccordionContent>
</AccordionItem>

<AccordionItem value="fetch-failed">
<AccordionTrigger>fetch failed</AccordionTrigger>
<AccordionContent>
The registry is unreachable. Check `FRAKMENT_REGISTRY` or your network. For local dev, run `FRAKMENT_REGISTRY=http://localhost:3000 npx frakment-mcp`.
</AccordionContent>
</AccordionItem>

<AccordionItem value="agent-blind">
<AccordionTrigger>Agent does not see the tools</AccordionTrigger>
<AccordionContent>
Verify the client config JSON parses, and that `npx -y frakment-mcp` runs from a terminal without errors.
</AccordionContent>
</AccordionItem>

</Accordion>


## Source

The MCP server lives in the [`mcp/` directory](https://github.com/hanshapd/frakment/tree/main/mcp) of the Frakment repo. It is a thin wrapper over the registry JSON with no interpretation logic. Browse the source on [GitHub](https://github.com/hanshapd/frakment/tree/main/mcp).
