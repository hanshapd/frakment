<Callout type="info" title="What is a skill?">
  A skill is a `SKILL.md` file that teaches an agent one focused capability.
  Frakment ships skills that let any agent discover, fetch, and install
  components without guessing.
</Callout>

Frakment publishes skills that follow the Agent Skills protocol. Each skill is self-contained, versioned in the repo, and served at a stable URL so agents can load it on demand.

## Why skills?

Agents that rely only on tools are blind to context. Skills fill the gap: they describe **when** to act, not just **what** to call.

## How agents load skills

<Steps>
  <Step>Discover the available skills</Step>

```bash
curl https://frakment.vercel.app/.well-known/agent-skills/index.json
```

<Step>Fetch the skill markdown</Step>

```bash
curl https://frakment.vercel.app/.well-known/agent-skills/site-skill.md
```

<Step>Load into context</Step>

Feed the markdown into the system prompt or tool context. The frontmatter description is what triggered the load; the body is what the agent follows.

</Steps>

## Anatomy of a skill

<Callout type="info" title="Two parts, one file">
  Every skill is a single `SKILL.md` file: YAML frontmatter at the top, markdown
  body below.
</Callout>

```yaml title="SKILL.md"
name: frakment-usage
description: Load when an agent needs to discover, fetch, or install Frakment components.
allowed-tools: ["fetch", "bash"]
version: 0.1.0
```

## Authoring a skill

<Steps>
  <Step>Create the folder and SKILL.md</Step>

<FileTree>
  <FileTreeFolder name="skills" defaultOpen>
    <FileTreeFolder name="my-skill" defaultOpen>
      <FileTreeFile name="SKILL.md" />
    </FileTreeFolder>
  </FileTreeFolder>
</FileTree>

<Step>Register it in frakment.json</Step>

```json title="frakment.json"
{
  "skills": [
    {
      "name": "my-skill",
      "source": "skills/my-skill/SKILL.md",
      "version": "0.1.0"
    }
  ]
}
```

<Step>Build and publish</Step>

```bash
npm run registry:build
```

</Steps>

## FAQ

<Accordion type="single" collapsible>

<AccordionItem value="difference-skill-mcp">
  <AccordionTrigger>
    How is a skill different from an MCP tool?
  </AccordionTrigger>
  <AccordionContent>
    A skill is documentation: prose that tells an agent how to act. An MCP tool
    is executable: a function the agent can call. Skills describe intent, MCP
    tools perform actions.
  </AccordionContent>
</AccordionItem>

<AccordionItem value="required-hosting">
<AccordionTrigger>Do I need to host skills myself?</AccordionTrigger>
<AccordionContent>
No. Frakment publishes skills at `/.well-known/agent-skills/index.json` and `/skills/<name>/SKILL.md`. Point your agent there.
</AccordionContent>
</AccordionItem>

<AccordionItem value="agent-skills-protocol">
  <AccordionTrigger>What is the Agent Skills protocol?</AccordionTrigger>
  <AccordionContent>
    An emerging convention for exposing `SKILL.md` files at predictable URLs so
    agents can discover and load them at runtime. Frakment follows the
    `schemas.agentskills.io` discovery schema.
  </AccordionContent>
</AccordionItem>

</Accordion>
